# 小米 SU7 Ultra 两个 AC mod 的驾驶物理检查

量产目标现已区分普通双腔空悬与赛道套装绞牙，轮胎独立记录。当前来源 mod 只有一套固定悬架，硬件归属未确认；本实验 Street/Sport/Track 仅为电控模式，未实现两种悬架。详见[空悬/绞牙版本与 mod 实现说明](../su7-sim/vehicle-variants.zh-CN.md)。


检查日期：2026-10-09。对象为 `msk_stw_xiaomi_su7_ultra - 2.0` 量产版与 `negi_su7_ultra_prototype` 原型版。

这次检查的是驾驶物理。已读取量产版的 data 和扩展脚本，并将原型版 data.acd 解包到独立分析目录进行对照。原始 mod 没有修改；原型 data.acd 解包前后的 SHA256 相同。尚未进入 Assetto Corsa 试驾或采集遥测，因而下文把配置事实、还原缺口与需要实测的驾驶症状分开说明。

## 最主要的结论

量产版有两类不同的问题。它比原型版更重、轮胎和下压力也不同，这些会自然增加驾驶难度；同时，它对电动车控制系统的模拟比较简化，最明显的是三电机扭矩分配、驾驶模式和回收制动。优化应先确认空悬或绞牙目标及实际轮胎，再补控制系统，并根据同配置遥测调底盘和轮胎。

目前没有足够证据判定某一个悬架数值写错后导致了所有“难开”反馈，也不能用“应该和原型车一样好开”作为正确标定的目标。

## 1. 优先级最高：四驱与稳定控制的还原

[量产四驱配置](<../car/msk_stw_xiaomi_su7_ultra - 2.0/data/drivetrain.ini:19>) 的基础前轴份额是 22%，后轴 78%，前加速锁止 0.50、后加速锁止 0.80；原型版对应为前 20%、前锁止 0.40、后锁止 0.60。量产版的后桥基础锁止比原型更高。

活动的 [物理脚本](<../car/msk_stw_xiaomi_su7_ultra - 2.0/data/script.lua:1>) 只有超过 360 km/h 切电门。电子配置里的 EDL 是给转得较快的轮子施加刹车，不能等同于左右后电机主动分配驱动、回收扭矩。已检查的加载配置中，没有找到按照转向、横摆和侧滑实现三个独立电机扭矩矢量控制的逻辑。小米官网明确列出了实车的三电机扭矩矢量控制系统。[车型官方说明](https://www.xiaomiev.com/ultra)

驾驶影响是有依据的推断：加油时较高的后桥锁止可能让车辆不愿转弯，超过后轮抓地极限后又转为动力过度转向；缺少主动横摆控制会使驾驶员需要自己承担更多电门和反打控制。具体是否出现这种“先推头、再突然甩”的过程，需要等半径弯和出弯遥测确认。

优化方向：建立每个电机的转速—扭矩边界，联动前后分配、后轮左右分配和轮胎滑移目标；把横摆稳定控制与 EDL 协调起来。先验证所用 CSP 版本的独立轮端控制接口，再实现对应逻辑。仅降低机械差速锁可以改善手感，但仍属于近似模型。

若先做诊断版，可以在其他条件不变时比较后动力锁止 0.80、0.65、0.50 三组，观察出弯转向需求和后轮滑移。它们是排查候选值，不是已知的实车标定值。`ctrl_single_lock.ini` 的实际自动加载规则还需结合运行版本确认，不能仅因没有显式引用就认定它绝不生效；也不能把这个差速器控制文件视作已实现三电机。

## 2. 驾驶模式目前主要是动力地图

[发动机模式配置](<../car/msk_stw_xiaomi_su7_ultra - 2.0/data/engine.ini:31>) 定义运动、排位、耐力、直线四张转速—扭矩倍率图，默认是排位。已检查的配置没有将模式切换关联到电门请求曲线、TC 目标、稳定控制、回收或悬架状态。

用功率公式和 LUT 线性插值计算，四个模式的模型峰值分别约为 781、929、759、961 kW。这是模拟使用的等效输出，可能包含作者约定的传动损耗；不能直接与厂家电机标称功率相比后判定马力错误。计算脚本与结果保存在 [动力估算](<drivetrain-estimates.json>)。

优化方向：至少区分街道与赛道两种整套控制配置。街道模式应有更渐进的电门请求、较严格的滑移和横摆控制；赛道模式允许更高输出和更多滑移。切换模式时，各项控制平滑过渡。默认使用排位地图，会让首次驾驶更容易接触到高功率状态，但这不是配置格式错误。

若先提供易用预设，可使用 PZ5 胎、运动地图和较严格 TC，再另外保留 Trofeo RS 的赛道预设。不要把所有预设都简单减马力后称为更还原。

## 3. 轮胎与 TC：冷态和低速值得优先复现

[默认轮胎](<../car/msk_stw_xiaomi_su7_ultra - 2.0/data/tyres.ini:8>) 是索引 1，即 Trofeo RS，而非 PZ5。Trofeo 的温度曲线在 20°C 时是 0.86，75–110°C 为 1.00；PZ5 在 20°C 为 0.985。因而冷态 Trofeo 比最佳温度下少约 14% 的温度抓地系数，刚出维修区时更容易触及极限。这一现象有明确配置依据，且半热熔胎需要预热符合官方使用说明。原型默认光头胎在 20°C 的因子是 0.80，冷胎敏感并非量产版独有的问题。

Trofeo 冷压设 30 psi，理想压力 40 psi。两者相差 10 psi 不能直接判成错误，因为理想值是运行压力，而非要求冷态就设置为 40。应该看连续几圈后的热压和核心温度，再调整冷压、热模型或理想压力。

量产胎的参考载荷 FZ0 为前 3100 N、后 3460 N，明显低于这辆重车的静载。实际抓地还受到负荷敏感、外倾、温度、压力和组合滑移影响，不能只对比 DY_REF，也不能通过改 WIDTH 一个数值增加抓地。WIDTH 在 AC 中主要控制轮胎痕迹宽度，真正需要标定的是轮胎力学参数。[物理参数说明](https://github.com/archibaldmilton/Girellu/wiki/Physics-Pipeline/686faddc31d1ae226258ba28a0cdc1be11f2e4a2)

[TC 配置](<../car/msk_stw_xiaomi_su7_ultra - 2.0/data/electronics.ini:14>) 在 12 km/h 以下不介入；TC LUT 从 0.10 到 0.40，其中从 0.16 到 0.28 的档位跳变较大。对于这种高输出电动车，应优先看低速起步和低速出弯在介入前是否发生轮速突增。基础字段 0.28 不是所有档位一直使用的阈值；量产版同编号的一些档位甚至比原型更严格，不能笼统说量产 TC 一定更松。原型的最低介入速度甚至设为 25 km/h，因此低速不介入也不是量产独有错误。

优化方向：确认玩家实际选择的 TC 档位，记录目标滑移和介入信号；增加低速扭矩请求限制或起步控制，让 TC 各档的效果逐渐变化；再标定负荷敏感、组合滑移和温压曲线。不要为了让冷胎好开而把半热熔胎的所有温度都设成满抓地。

## 4. 回收制动使用了线性发动机制动近似

[松电门拖曳配置](<../car/msk_stw_xiaomi_su7_ultra - 2.0/data/engine.ini:15>) 是 FROM_COAST_REF，350 Nm @ 28500 rpm，线性增加。总传动比为 9.205。按后轮未加载半径 0.352 m、质量 2435 kg，忽略风阻、滚阻和损耗估算，100 / 200 / 300 km/h 时的这部分拖曳分别约为 0.093 / 0.187 / 0.280 g。它们是公式示意，不是实际减速度。

未看到按驾驶模式、刹车请求、电池状态和回收功率边界协调制动力的逻辑。因此“松电门后的减速”和“踩刹车时回收与摩擦制动的混合”没有完整还原。直接采用单一拖曳曲线，会使电动车的入弯节奏和真实控制逻辑存在差别。

优化方向：分开标定松电门请求与踩刹车请求，让回收和摩擦制动共同跟随目标减速度，并保证前后轴滑移和稳定性。厂家公布的最大回收减速度属于能力边界，不能据此把松电门设置为全程恒定的最大回收。

## 5. 悬架、转向和刹车：重点待验证项

量产前后轮率约 89.8 / 77.6 kN/m，原型约 135 / 145 kN/m；量产防倾杆为 34 / 18.5 kN/m，原型 60 / 28 kN/m。量产 mod 更软是配置事实；尚未确认它对应普通空悬还是赛道绞牙，不能据此判定底盘已还原。用单轮簧上质量和线性轮率估算，量产前后频率约 2.07 / 1.89 Hz，原型约 2.79 / 2.84 Hz；这个近似未计轮胎柔度、渐进轮率与整车耦合。应根据压缩行程、轮胎垂向载荷和外倾变化判断效果，而不是直接照抄原型。

量产前低速压缩阻尼 13455、后 7527 N·s/m，前后差异明显，适合排查制动转向响应、颠簸接地和弯中推头；但阻尼还与轮率、簧上质量、高速分段和限位行程共同作用，目前不能仅因数值大就判错。后轮使用 DWB 近似，同样需要看实际几何产生的外倾与前束变化，不能因类型名称就认定模拟不成立。

量产方向盘半锁角 405°，原型 270°，转向比都为 12.2。半锁角不同不等于转向比不同。应核对方向盘自动匹配、实际前轮转角和几何，而不是只缩短 STEER_LOCK 来制造更快响应。

量产 FFMULT 为 1.36，原型 1.12，在其他条件相同下 FFB 增益高约 21%。这可能增加力反馈饱和的机会，从而掩盖前轮接近极限的细节；需要在实际方向盘上观察 clipping。降低 FFB 增益可以改善反馈，但不会增加车辆的物理抓地。

刹车最大扭矩为 4650 Nm、前份额 64%，原型 4800 Nm / 65%；量产还有 ABS。不能凭这些字段判定制动力不够，也不能把备用 brakes_temp 文件里的未使用曲线当作当前错误。按名义胎半径和最大机械扭矩粗算，忽略气动、附着、ABS 和拖曳回收，量产机械扭矩上限对应约 1.10 g，原型约 1.40 g；这是检查合成制动力的线索，不是实测刹车减速度。优先测 100→0、200→0 的停车距离、四轮滑移与 ABS 介入，随后再调整总扭矩、前后分配和混合回收。

setup 的前外倾范围 −1.5° 至 +0.1°、后 −3° 至 −0.6° 值得检查界面能否覆盖目标调校；STEP=1 不能直接理解成 1° 一格，Content Manager 对 CAMBER 使用专门的缩放与步长规则。[作者源码](https://github.com/gro-ove/actools/blob/master/AcManager.Tools/Objects/CarSetupEntry.cs#L99) 默认前 −1.5° 已是菜单允许的负外倾最多的一端；若热胎遥测证实外侧前胎外肩过热，可以先开放小范围调节。

## 6. 原型车容易开，有相当一部分是车型本身的优势

两份配置的总质量分别是量产 2435 kg、原型 1975 kg，相差 460 kg，量产重约 23%。这些是包含 mod 质量约定的配置值，不应直接与不含驾驶员的厂家整备质量混用。

原型默认是 Pirelli Slick DHH 光头胎，而量产默认 Trofeo RS；原型还采用更大的负外倾。它们的胎宽标注分别是前后 310 / 340 mm 与 265 / 305 mm，参考摩擦和负荷敏感参数也不同。

气动差距更大。按各气动面离地 50 mm、零俯仰和侧滑、空气密度 1.225 kg/m³ 的静态估算：

- 100 km/h：量产约 24 kgf，原型约 180 kgf。
- 200 km/h：量产约 95 kgf，原型约 718 kgf。
- 300 km/h：量产约 213 kgf，原型约 1616 kgf。
- 350 km/h：量产约 291 kgf，原型约 2200 kgf。

估算量产气动前份额约 34.8%，原型约 44.3%。原型高速时获得的额外抓地尤其大，前轴得到的支持也更多。计算不是 CFD 或 AC 实测，实际气动面离地、俯仰和损伤都会改变结果。

量产估算在 350 km/h 时约 291 kgf，接近官方最大 285 kg 下压力的数据。因此“量产下压力远小于原型”本身不是 mod 错误。不要给量产直接增加成原型规模的下压力后称为还原。[量产气动数据与测试速度](https://www.xiaomiev.com/ultra)

完整输入和估算见 [物理对照数据](<physics_baseline_comparison.json>)。

## 7. 已排除的几个容易误判的点

- FRONT_SHARE=22 写法正确，AWD 这里采用 0–100 的完整百分数，代表前轴 22%。改成 0.22 会改变含义。[参数规则](https://github.com/archibaldmilton/Girellu/wiki/Physics-Pipeline/686faddc31d1ae226258ba28a0cdc1be11f2e4a2)
- TORQUE_MODE_EX=2 是 CSP 推荐的悬架反作用力计算模式，不是明显错误。[CSP 悬架文档](https://github.com/ac-custom-shaders-patch/acc-extension-config/wiki/Cars-%E2%80%93-Suspension)
- tyreload.lua 根据轮胎受力改变网格显示，没有施加新的轮胎力，不能解释成它让抓地突然变化。
- engine.ini 选用 FROM_COAST_REF，备用 COAST_CURVE 写 coast.lut 不等于这个缺失文件必然影响当前运行。
- ERS__ 目录里的实验文件不能作为活动三电机控制已经完成的证据。已检查的加载配置没有指向它；未来启用时应重新审查。
- 后翼的 60–66 km/h 速度控制看起来切换较快，但对应 CL 只约从 0.152 到 0.160，总下压力变化很小。目前不能把它列为主要失稳原因。

## 建议实施顺序与验证

第一阶段，先做可复现基线：固定 CSP 版本、启用所需扩展物理，固定赛道、气温、路面抓地、胎种、热态胎压、动力模式和 TC 档。记录方向盘输入方式。先比较冷胎与热胎，以及 PZ5 和 Trofeo RS。

第二阶段，补电动车控制：驾驶模式联动、低速扭矩请求、横摆/滑移控制、后轮左右分配与混合回收。用下列动作验证，再决定底盘是否要动。

- 0–30 km/h 分级电门起步：看 TC 介入前的轮速、扭矩和车身横摆。
- 固定半径弯，逐步增加电门：看转向不足梯度、前后滑移和是否出现推头转甩尾。
- 100 / 200 / 300 km/h 松电门，以及 100→0 / 200→0 刹车：区分回收、风阻和摩擦制动。
- 同一段颠簸和路肩：看悬架触限位、轮胎卸载、前后束角与外倾变化。
- 各模式 0→100、100→200：验证功率曲线、牵引力和控制介入，而不是仅对齐面板马力。

第三阶段，用遥测校准底盘和轮胎：轮载、悬架位移、轮胎核心温度/压力、组合滑移、实际前轮转角和 FFB clipping。每次只改一个因素，比较同一动作的重复结果。

如果只是想提供更容易上手的版本，可以单独提供舒适/街道预设；如果目标是还原实车，最值得投入的是电机、稳定控制和制动请求的协调。两种目标应明确标注，避免把增加抓地、减重或增加巨大下压力当成实车还原。

更多底盘参数、计算假设和引用见 [底盘审计补充](<chassis-findings.zh-CN.md>)。
